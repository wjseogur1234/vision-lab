## 2. 폴더 구조

세 하위 데이터의 구조는 같다.

```text
01.데이터/
├── 1.Training/
│   └── 교통안전(Bbox)/
│       ├── 1.라벨링데이터_230510_add/
│       │   └── 1.라벨링데이터.zip        라벨 전체가 zip 1개
│       └── 2.원천데이터/
│           ├── <장소>.zip                 장소마다 zip 1개
│           └── <장소>.zip.part<오프셋>    조각난 zip
└── 2.Validation/
    └── (같은 구조)
```

- 이미지는 폴더가 아니라 zip 안에 있다.
- zip 파일 이름은 공백 대신 `_`를 쓴다. zip 안의 폴더 이름은 공백을 쓴다.
  예: 파일 `소신여객_앞.zip`, 안쪽 폴더 `소신여객 앞/`.

### 2.1 zip 안의 경로

| 종류 | 경로 |
|---|---|
| 이미지 | `<장소>/<카메라ID>/<파일 이름>.jpg` |
| 라벨 | `<장소>/<카메라ID>/<장소>_<카메라ID>.json` |

- 라벨은 카메라마다 JSON 1개다.
- 이미지 파일 이름 예: `20201020_055957_S_3069.jpg`. 날짜, 시각, 프레임 번호가 들어 있다.
- 카메라 ID 예: `BC2000105`, `SC0041701`.

> [!question] 카메라 ID의 앞 글자
> `BC`는 부천, `SC`는 대전으로 보인다. 장소 이름에서 추측한 것이다. 확인하지 않았다.

### 2.2 조각난 zip

파일 이름 끝의 숫자는 바이트 오프셋이다. 예: `.zip.part0`, `.zip.part1073741824`.

| 위치 | 조각난 zip | 조각 수 |
|---|---|---|
| Training / Bbox | 멀뫼사거리, 사단사거리, 유성네거리 | 각 2개 |
| Training / Bbox | 삼정고가교 | 3개 |
| Training / Bbox | 용반네거리 | 4개 |
| Training / Bbox | 범계사거리 | 1개 |
| Training / Segmantation | 멀뫼사거리, 사단사거리, 삼정고가교, 용반네거리, 유성네거리 | 각 1개 |
| Validation / Bbox | 멀뫼사거리, 용반네거리 | 각 1개 |

- 조각이 1개뿐인 파일도 이름에 `.part0`이 붙어 있다.
- 모든 조각 묶음에서 오프셋이 끊김 없이 이어진다. 첫 조각은 zip 머리(`PK\x03\x04`)로 시작하고, 마지막 조각에 zip 끝 표시가 있다.
- 조각을 실제로 이어 붙여서 열어 보지는 않았다.

### 3.3 라벨 JSON 형식

COCO와 비슷하지만 표준과 다르다. 최상위 키는 `info`, `images`, `annotations`, `categories`, `guideline`, `meta`다.

```json
{
  "images": [
    {"id": 369411, "file_name": "BC2000201/20201017_140001_S_23166.jpg",
     "meta_id": 3237, "frame_value": 23166}
  ],
  "annotations": [
    {"id": 369411, "image_id": 369411,
     "bbox": [[1058.2, 355.3, 1110.9, 399.4], [626.2, 533.1, 660.8, 625.0]],
     "category_id": [1, 7],
     "tracking_id": [], "segmentation": [], "area": 0.0, "iscrowd": "Y"}
  ],
  "categories": [{"id": 7, "name": "보행자"}],
  "meta": [
    {"id": 3221, "camera_id": "BC2000201", "date": "2020-10-14", "time": "1:59:58",
     "weather": "Sunny", "time_space": "새벽", "resolution": "FHD", "fps": 10}
  ]
}
```

표준 COCO와 다른 점:

| 항목 | 이 데이터 | 표준 COCO |
|---|---|---|
| `annotations` 1개 | 이미지 1장의 상자 전체 | 상자 1개 |
| `bbox` | 상자 목록. 상자는 `[x1, y1, x2, y2]` 픽셀 | `[x, y, w, h]` |
| `category_id` | 목록. `bbox`와 순서가 같다 | 숫자 1개 |
| `images`의 `width`, `height` | 없다 | 있다 |

- 이미지 크기가 라벨에 없다. YOLO 형식으로 바꾸려면 이미지 파일에서 크기를 읽어야 한다.
- 좌표가 이미지 밖으로 나간 예가 있다. 높이 1080인 이미지에서 `y2 = 1085.77`이 나왔다.
- `images[].meta_id`가 `meta[].id`를 가리킨다.

> [!question] `guideline`
> 좌표 목록이 들어 있다. 예: `[[0.0, 0.0, 0.0, 244.0, 1920.0, 248.0, 1920.0, 0.0, 0.0, 0.0]]`.
> 라벨링에서 제외한 영역으로 보인다. 확인하지 않았다.

### 3.4 촬영 조건 (`meta`)

기준: 촬영 구간(`meta`) 수.

| 항목 | Training | Validation |
|---|---|---|
| 날씨 | Sunny 2,193 / Rainy 451 / Cloudy 236 / Foggy 53 / Snow 53 | Sunny 1,212 / Rainy 209 / Cloudy 86 / Foggy 19 |
| 시간대 | 오전 997 / 낮 856 / 오후 792 / 새벽 341 | 오전 502 / 낮 438 / 오후 388 / 새벽 198 |
| 해상도 | FHD 1,823 / HD 1,161 / 빈 값 2 | FHD 1,067 / HD 459 |

`meta`에는 `week_day`, `crosswalk`, `blocked`, `height`, `light`, `lines`, `direction`, `road_type`, `address`도 있다.

## 4. 교통안전(Tracking)

- 라벨 형식은 Bbox와 같다. `tracking_id` 목록이 채워져 있다.
- 연속 프레임이다. 이미지 이름 예: `BC1001201/fps_20_20201122_170000-1_0000.jpg`.
- Training: 카메라 6대, 원천 zip 11개(추가분 `2.원천데이터_230522_add` 1개 포함).
- Validation: 카메라 1대(`BC1001201`), 이미지 37,200장(라벨 기준).

> [!warning] 열리지 않는 zip
> `2.Validation/교통안전(Tracking)/2.원천데이터/소사회주로삼거리.zip` (16,006,289,920바이트)이 zip으로 열리지 않는다.
> zip 머리는 있지만 파일 끝에 zip 끝 표시가 없다. 내려받기가 끝나지 않았거나 뒤쪽 조각이 빠진 것으로 보인다.
> 101의 다른 zip은 모두 열린다.

## 5. 교통안전(Segmantation)

- 라벨 형식은 Bbox와 같다. `bbox`는 비어 있고 `segmentation`에 다각형 좌표가 있다.
- Training: 라벨 JSON 61개, 원천 파일 35개.
- Validation: 라벨 JSON 39개, 원천 파일 9개, 이미지 3,087장(라벨 기준).
